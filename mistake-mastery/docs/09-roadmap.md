## 2. 第 0 步：开通接口，用真实卷子试水（本周）

**目标**：花两三个晚上，在写正式代码之前，把服务器和数据仓库准备好，并确认关键能力在自家孩子的卷子上管用。

| 事项 | 做法 | 看什么 |
|------|------|--------|
| 开通接口 | 阿里云百炼（通义）、火山方舟（豆包）各开一个 API Key；擦除接口开通百度、有道、TextIn 中的两三家（都要实名认证）；各 AI 平台开启预算告警 | 能调通 |
| 服务器与域名 | 买一台香港轻量服务器（2 核 2G）和一个域名，域名解析到服务器 | 手机能打开服务器上的测试页 |
| 数据仓库 | 在 GitHub 新建**私有**仓库（如 `xuetou-data`），给服务器生成部署密钥并加到仓库（勾选写权限）；GitHub 账号开启两步验证 | 服务器上能 `git push` |
| **测连通性** | 在服务器上：调一次各家 AI 和擦除接口；推送一次数据仓库；手机在 4G 和家里 Wi-Fi 下各上传一张照片 | 接口不超时；推送顺利；上传速度可以接受 |
| 准备素材 | 拍孩子最近的 10 页卷子：数学几何图、物理电路图、红笔批改都要有 | — |
| **试擦除** | 用小脚本把 10 页分别送到各家擦除接口，并排对比 | 几何辅助线和红笔擦干净没有；印刷线条有没有被擦坏 |
| **试识别** | 同样 10 页：视觉大模型直接切题 + 识别，与专门的切题接口对比 | 切题准不准；公式和图形认得对不对；知识点分得对不对 |
| **试出题** | 挑 5 道错题，让模型按变式阶梯各出 5 题，另一家模型盲解 | 答案对不对；像不像北京的题；有没有超纲 |
| 填信息 | 孩子所在区、教材版本、本学期考试日期 | 见 [01 §2.2](01-product-requirements.md) |

**产出**：服务器、域名、私有数据仓库就绪；选定擦除接口和模型搭配（补全 [05 §2](05-ai-design.md) 的路由表）；把试水用的题和答案整理成最初的评测集（`evals/`）。

## 3. 各版本内容

### v0.1 能拍、能擦、能打印（约 3 周）

> **先做本地版**：跑在家里的电脑上，手机连家里 Wi-Fi 访问；数据从第一天起就同步到 GitHub 私有仓库。下表中的"部署"一行（Caddy、HTTPS）等转到公网时再做。
>
> **进度（2026-10-13）**：除"部署"一行外，下表内容已实现并通过测试（含浏览器端到端走查）。还没做的是**用真实卷子和真实接口验证**：各家去手写和识别切题的效果、接口返回格式，需要填好密钥后按 [SETUP.md](../SETUP.md) 第 5 步跑一遍。

| 范围 | 完成标准 |
|------|----------|
| 项目骨架：FastAPI + SQLite + React；孩子档案；知识点和错因字典导入 | — |
| 部署：Docker + Caddy（HTTPS）；登录 + 限速 + 退出所有设备；所有文件走鉴权接口；每日费用上限 | 手机在外面也能通过 HTTPS 打开、登录；输错 5 次密码会被锁 |
| 拍照上传（单题、整页、多页）→ 矫正 → 切题（自动 + 手动框选兜底）→ 结构化识别 → 分类 | 拍一份 3 页月考卷，几分钟内在批量确认页看到切好的题 |
| 整页擦除 + 预览 | 擦除图和原图可以对比 |
| 答案：卷面答案或手动输入优先，否则 AI 单模型解答并标"⚠ 待核" | — |
| 打印：原卷还原、错题重做单（作答区按原卷留白）；打印记录 | 拿到 PDF，家用打印机打出来清晰 |
| 错题本列表（按学科、知识点、来源） | 能找到录入过的题 |
| 同步到 GitHub：导出 JSONL、自动提交推送、同步状态；恢复脚本 | GitHub 私有仓库里能看到每次录入的提交；**在一台新机器上用恢复脚本把数据完整恢复出来**（这一步一定要实际演练一次） |

> **知识点整理（2026-10-15，提前做了）**：错题本里"按知识点看"：每个考点的掌握度（06 §6 的公式）、掌握死角排序并写明原因、还没有错题记录的常考点、每个知识点的错题和题库同类题；首页显示最该补的 3 个考点。算法见 [06 §6.1](06-mastery-algorithm.md#61-知识点整理页已实现2026-10)。v0.3 的"简版看板"可以在这个基础上做。薄弱知识点还可以让 AI 按孩子自己的错题写一份**知识点讲解**（要点、方法、他容易错在哪、例题，可以打印），见 [06 §6.2](06-mastery-algorithm.md#62-知识点讲解已实现2026-10)；v0.3 的"五步分步讲解"讲的是一道题，两者互补。
>
> **题库导入（2026-10-13，提前做了）**：导入真题、各区一模二模、区统考的 PDF（或照片），切成带官方答案的题；拍照录入时自动匹配，带上官方答案和出处。设计见 [10](10-question-bank.md)。和 v0.1 一样，还需要用真实卷子验证。

## 4. 开发方式

- **每个版本拆成若干次 Claude Code 会话**，每次完成一块能运行的功能，提交到 git。
- **纯逻辑写单元测试**：状态机（06 §7）、复习调度、排版分页、同步导出都是纯函数，用测试守住，改参数不怕改坏。测试只用虚构的题目和数据。
- **小型评测集**：从孩子卷子上积累约 30 道"题目 + 标准答案"，**放在私有数据仓库里**；换模型或改提示词之前跑一遍，确认没有变差。
- **代码位置**：先放在本仓库的 `mistake-mastery/` 目录下；想独立出去时再拆成单独的仓库。**本仓库是公开的**，提交前确认没有夹带孩子的数据或密钥。

## 5. 风险

| 风险 | 应对 |
|------|------|
| 家长时间不够，版本拖期 | 版本切小；每个版本先做最常用的环节；没做完的环节用现成工具顶上 |
| 擦除效果不好（尤其是图形题） | 第 0 步先试三家；修补画笔兜底；实在不行用夸克扫描王处理后再上传 |
| AI 出题或解答出错 | 交叉校验；"⚠ 待核"由家长确认；变式题可以一键作废重出；打印件标注"AI 生成"，鼓励孩子发现错误 |
| 孩子不愿意用 | 控量（默认每天 20 分钟）；以纸面练习为主；每日时长和孩子商量着定；不展示让孩子有压力的数字 |
| 服务器出故障或被攻破 | 数据正本在 GitHub，新开一台服务器就能恢复（§3 v0.1 已演练）；部署密钥只能写数据仓库；被攻破时作废所有密钥、重建服务器 |
| 网站被盗刷 AI 接口 | 登录限速 + 每日费用上限 + 平台预算告警 |
| GitHub 推送失败 | 提交先留在服务器上自动重试；设置页能看到同步状态 |
| 不小心把孩子的数据提交到公开仓库 | 数据只写进私有数据仓库；代码仓库的 `.gitignore` 排除数据目录；万一提交了，要从 git 历史里彻底清除，而不只是删掉文件 |
